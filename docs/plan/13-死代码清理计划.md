# 13 · 死代码清理专项计划

> 本文件是拆分方案的 Phase 8.5。目标：在不改变任何用户可见行为的前提下，把 `#![allow(dead_code)]` 掩盖掉的死代码清掉或明确标注，让编译器重新成为维护者。

## 1. 为什么死代码必须作为独立专项

- `src/main.rs` 顶部有 `#![allow(dead_code)]`，普通 `cargo check` **看不到**任何 dead_code 告警。
- 拆分阶段不能顺手删代码：机械移动期间先“搬得一模一样”，否则无法区分“移动出错”和“删代码引发回归”。
- 只有等 Phase 0–8 的目录稳定后，再按模块清理，review 和回滚成本最低。

## 2. 暴露死代码的方法（不修改源码）

```bash
cd Miyu
RUSTFLAGS='--force-warn=dead_code' \
  cargo check --all-targets --message-format=short \
  2>&1 | tee /tmp/dead-code-report.txt
```

`--force-warn` 能越过源码里的 `allow` 帽子，把当前所有未使用项暴露出来。当前快照结果：

- 生产目标（bin "miyu"）：**103 条 dead_code 告警**。
- 测试目标（bin "miyu" test）：**72 条，其中 60 条与生产重复**。
- 覆盖约 45 个文件，其中 `agent/conversation.rs` 整个文件都是死代码。

## 3. 四类处置（先分类，再动手）

| 分类 | 含义 | 处置 |
|---|---|---|
| **D1 直接删除** | 生产与测试目标都不使用，且不参与 serde/协议/迁移 | 删除定义、声明、模块，必要时同步删除对应测试 |
| **D2 测试专用** | 只被 `#[cfg(test)]` 代码引用 | 加 `#[cfg(test)]` 或搬到测试模块，生产目标不再编译 |
| **D3 保留并标注** | serde 字段、IPC/导出协议字段、为近期功能保留的 API | 保留，局部 `#[allow(dead_code)]` + 注释原因 |
| **D4 语义死代码** | 代码“可达”但配置/参数/分支实际不生效 | 单独 PR：修复行为，或按废弃流程移除；**不在机械清理中顺手改** |

判定流程：

1. 对每个告警符号执行 `rg -n '\b<符号>\b' src`；
2. 只看声明行以外的引用：
   - 没有任何引用 → D1；
   - 只有 `#[cfg(test)]` 区间引用 → D2；
   - 有生产引用但编译器仍告警（宏/serde/动态名）→ D3；
3. 字段告警额外检查 `#[derive(Serialize, Deserialize)]`、IPC/JSON 契约、数据库列映射；命中任何一项先按 D3；
4. 告警所在的函数若在“扩展点/将来计划”清单（`todolist.md`、模块注释）中，先 D3，不擅自删。

## 6. D4：编译器发现不了的“语义死代码”

`dead_code` lint 只能发现未引用；以下属于“引用存在、但行为不生效”，用独立审计处理：

| 候选 | 说明 |
|---|---|
| `memory pending_events` 链路 | `remember_pending_event`/`flush_pending_events` 生产无调用；表结构仍建。需决定：接入真实写入，或删除表/函数 |
| `QqGroupManagementPluginSettings` 的 `max_groups`、`expired_record_retention_seconds`、`cleanup_interval_seconds` | 配置可读写，但生产代码未使用 |
| `QqMessageRecallPluginSettings.cancel_cleanup_interval_seconds` | 配置有校验，但代码未使用 |
| `hash_codec.decode_encoded_text.text_encoding` | 参数声明了但未实现 |
| `read_clipboard.preferred_type` | 参数校验但未实际过滤（若当前版本仍未改） |
| 历史遗留 tool description 字段/旧键 | 删除前必须核对 `config.rs` 的 `DEPRECATED` 映射与旧配置文件兼容 |
| `todolist.md` 中的规划项 | 如“权限管理、语音输入”等，不应视为死代码删除依据 |

D4 处置：

1. 每个候选单独 issue/PR，写明“当前无效果”；
2. 优先**实现缺失行为**（如果语义明确且低成本）；
3. 若不再需要：走“标记废弃 → 一个版本后删除配置项”，不得直接删配置键。

## 7. 与拆分阶段的先后关系

- Phase 0：把 `RUSTFLAGS='--force-warn=dead_code'` 报告纳入基线，但不处理。
- Phase 1–8：移动代码时**不清理**；若某符号因移动变成未使用，记录到 `/tmp/dead-code-report.txt`，留给本专项。
- Phase 8.5（本专项）：按 DC-1…DC-8 顺序清理。
- Phase 9：在 CI 中加入：

```yaml
- name: Dead code gate
  run: |
    RUSTFLAGS='--force-warn=dead_code' cargo check --all-targets --message-format=short 2>&1 | tee /tmp/dead-code-report.txt
    test $(grep -c 'never used\|never read' /tmp/dead-code-report.txt || true) -eq 0
```

例外白名单放在 `scripts/dead_code_allow.txt`（每行 `file:symbol:原因`），由脚本读取。

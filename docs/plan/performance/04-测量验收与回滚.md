# 04 · 测量、验收与回滚

## 1. 基线脚本

### 1.1 CPU / RSS 基线

在隔离 `MIYU_HOME` 下启动 daemon 并跑固定脚本：

```bash
MIYU_HOME=/tmp/miyu-perf-baseline miyu daemon start
PID=$(pgrep -f '__daemon' | head -1)

# 每 5 秒采样
while true; do
  echo "$(date +%s) $(awk '/VmRSS/{print $2}' /proc/$PID/status) $(awk '/VmHWM/{print $2}' /proc/$PID/status)"
  sleep 5
done | tee /tmp/miyu-perf-rss.tsv
```

CPU 采样：

```bash
perf stat -p $PID -a -- sleep 30
# 或
top -b -d 1 -p $PID | tee /tmp/miyu-perf-cpu.tsv
```

场景至少覆盖：

1. 空闲 10 分钟；
2. 单会话连续 20 轮纯文本；
3. 单会话 5 轮工具循环（`run_command` 大输出）；
4. WebUI 长会话滚动；
5. QQ/OneBot 未连接与连接后普通消息。

## 2. 验收门禁

| 指标 | 验收目标 |
|---|---|
| 功能 | `cargo test` 全绿；黑盒冒烟清单通过 |
| CPU 空闲 | daemon 空闲采样平均 CPU 与基线持平或下降 |
| CPU 活跃 | 同一固定工作负载的 user+sys 时间下降，且 actor 无 >500ms 同步阻塞 |
| RSS 长期 | 24 小时曲线平稳；无单调增长项 |
| 请求字节 | `requests-*.jsonl` 与 `cache-usage` 语义不变；涉及消息组装的 PR 必须做前缀回归 |
| 前端 | 长会话滚动 DOM 节点与 JS heap 不再随消息数线性增长 |
| VRAM | WebUI 空状态 GPU 内存下降；Kitty 重复图片不重复上传 |
| 3D/动画 | 后台标签页动画暂停；reduced-motion 静态降级 |

## 3. 提交与回滚

- 每个优化项独立 PR：`perf(cpu|mem|gpu): ...`。
- 一个 PR 只改一个性能主题，禁止夹带功能/结构改动。
- 回滚：单 PR `git revert`；不涉及数据库 schema 或导出格式。
- 若某项优化实测无明显收益，先不合并，避免徒增复杂度。

## 4. 性能优化与结构拆分的冲突控制

- 若目标文件已在结构性拆分分支中被移动，等待该拆分合入后再做性能优化。
- 性能优化中不得引入新模块依赖方向；如需要新工具模块，先走 `arch_dep_check.py`。
- 涉及 `agent/llm/tools/registry` 的优化，先跑字节前缀回归：
  - 固定会话连续两轮；
  - 比较第二轮 `cache_read` 不下降；
  - mock 请求断言第 N 轮是第 N-1 轮的前缀延伸。

## 5. 完成定义

1. CPU、内存、显存三项至少各落地一个 P1 优化；
2. 前端长会话渲染与轮询优化落地；
3. 所有基线指标有前后对比数字；
4. 全部功能冒烟与 `cargo test` 通过；
5. 连续运行 24 小时无 OOM、无持续增长；
6. 性能改动未引入任何新的语义/协议/数据格式变化。
